# Support

Start with the project's README and its repository-specific support instructions.

If its issue tracker is enabled and accepts questions, search existing issues before opening one. Include the relevant version, environment, steps to reproduce and sanitized error output. A response time is not guaranteed.

For a suspected vulnerability, follow the repository's security policy. Use GitHub's private vulnerability reporting option when the repository provides it. Do not post credentials, exploit details or private data in a public issue. This default does not establish a security contact or private reporting channel.

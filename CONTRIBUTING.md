# Contributing

Read the repository's README, contribution instructions and license before changing anything. Repositories may have different runtimes and contribution policies.

For a proposed change, describe the problem and the behavior you want. Check existing issues and pull requests first. Keep the change focused and preserve unrelated work.

Use the project's documented installation and verification commands. In a pull request, explain what changed, how you checked it and any remaining limitations. Include a screenshot when it helps explain a visible change.

Use sanitized examples. Keep credentials, personal data, customer records and private service details out of issues, screenshots and patches.
